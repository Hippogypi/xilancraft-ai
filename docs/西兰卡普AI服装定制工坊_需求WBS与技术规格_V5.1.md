# 西兰卡普非遗纹样 AI 服装定制工坊

**软件需求拆解（WBS）与技术规格说明书 V5.1**（含 V5.2 验收后微调增补，见 §12）  
文档性质：AI 主导开发的实施基线｜平台：微信原生小程序｜用途：服装设计类比赛 Demo｜预算约束：总支出 0 元  
状态：V5.1 基线已交付（tag `v0.1.0-demo`，P0 全链路验收通过）；§12 为验收后微调阶段的正式需求增补。

## 1. 产品目标与边界

### 1.1 产品目标

以土家族西兰卡普织锦为文化基础，通过“传统符号解构—几何重组—AI 纹样共创—服装效果预览—定制意向订单”形成完整体验。保留原 V4.0 的四大用户模块，并增加同一微信小程序内的管理员端：管理员可在交互界面配置、测试、启停及切换 AI 接口，查看生成记录与模拟订单。

**不可妥协的验收要求：评委现场输入新的提示词，点击生成后，必须由真实 AI 模型返回新图片。** 预置图片可用于素材库或故障说明，但不得替代核心生图验收。

### 1.2 范围内

- 原生微信小程序四个用户主页面：非遗导览、灵感素材库、AI 定制工坊、服装预览与定制意向。
- 同一小程序内受保护的管理员端：AI 服务配置、连接测试、服务切换、生成记录、订单管理。
- 本地 Node.js API 代理、SQLite 持久化、可插拔生图 Provider 适配层。
- 真实文生图（P0）；图生图（P1，依赖免费模型能力）；服装 PNG 纹样叠加与模拟订单。
- 3D 织机 MP4、TouchDesigner 动画、Style3D 服装 PNG 及贴图区域坐标的整合。

### 1.3 范围外

- 微信支付、真实付款、物流、实际服装生产和商业订单履约。
- 云数据库、付费云存储、长期付费托管、强制绑定个人云账户。
- 将大型生图模型直接打包进微信小程序客户端。
- 原计划书中的人员分工、周次时间线、商业正式上线承诺。

### 1.4 优先级与验收定义

- **P0（必做）**：现场真实文生图、API 管理与切换、四页基本交互、可用的服装预览、管理员登录、安全密钥管理、基础订单提交和查看。
- **P1（应做）**：图生图、生成记录持久化、订单状态流转、素材分类与文化说明、服装预览调节、隐私同意。
- **P2（增强）**：生成历史筛选、统计面板、预览导出、丰富动效与更多模板。

任务完成的统一标准（Definition of Done）：功能代码可运行；具有正常/异常路径；数据传递与持久化验证通过；提供可复现的验收步骤；不泄露密钥；不产生费用。

## 2. 用户角色与主业务流程

| 角色 | 权限 | 入口 |
|---|---|---|
| 访客/普通用户 | 浏览文化和素材、AI 生图、服装预览、提交模拟定制意向 | 四 Tab 用户端 |
| 管理员 | 登录、维护 AI Provider、测试连接、切换服务、查看生成记录和订单、修改订单状态 | 小程序内隐藏入口 + 登录校验 |

**主流程 A（AI 设计）**：首页/素材库 → AI 工坊 → 输入提示词/选择风格与参考纹样 → 生成任务 → 后端调用真实 AI → 结果显示 → 选择用于服装预览。

**主流程 B（定制意向）**：服装模板 → 叠加生成纹样 → 调整位置与尺寸 → 填写表单并主动同意隐私说明 → 提交订单 → 管理员查看与修改状态。

**主流程 C（切换 API）**：管理员登录 → 新建或修改 Provider 配置 → 连接测试/测试生成 → 确认免费额度及服务可用 → 激活该配置 → 用户端后续生成请求使用新 Provider。

## 4. 技术架构与运行环境

### 4.1 逻辑结构

```text
[微信原生小程序]
  ├─ 用户端：文化 / 素材 / AI 工坊 / 服装预览与订单
  └─ 管理端：登录 / API 配置 / 生成记录 / 订单
             │ HTTP(S)
             ▼
[Node.js + Express 统一 API 服务]
  ├─ 管理员鉴权与会话
  ├─ Provider 配置管理（密钥只留服务端）
  ├─ AI 任务编排 + Provider Adapters
  ├─ 订单服务
  ├─ SQLite（配置、任务、订单）
  └─ 本地文件目录（生成图片、订单预览）
             │
             ├── 免费云端图像生成 API A
             ├── 免费云端图像生成 API B
             └── 可选本地 ComfyUI 服务
```

### 4.2 技术选型

| 层级 | 选型 | 理由与约束 |
|---|---|---|
| 小程序 | WXML + WXSS + JavaScript + 微信原生 API | 保证是微信原生小程序，不使用 H5 替代 |
| 前端状态 | 页面 `data` + 轻量共享状态模块 | Demo 规模下减少依赖 |
| 后端 | Node.js LTS + Express | 轻量，适合 AI 编程和接口代理 |
| 数据 | SQLite（建议 `better-sqlite3` 或等效库） | 本地文件持久化、零云数据库成本 |
| 图片文件 | 本地 `data/uploads`、`data/generated` | 保存生成结果，避免第三方临时 URL 过期 |
| API 认证 | 管理员登录 + HttpOnly 会话或短期 Token | 小程序端使用时应选择适合 `wx.request` 的会话方案 |
| AI 接入 | Provider Adapter 接口 | 隔离不同模型的请求、响应与轮询协议 |
| 配置 | `.env` + SQLite 加密敏感字段 | 密钥不写在小程序代码和仓库中 |
| 服装预览 | 先用图片绝对定位叠加，导出再用 Canvas | 优先保证实时预览 |

### 4.3 演示部署模式

**模式 A：电脑开发者工具演示（默认目标）**：小程序在微信开发者工具模拟器中运行；本机启动 Node.js 服务；开发环境可按工具配置调试本地接口。需要真实互联网访问云端 AI。

**模式 B：手机真机演示（条件扩展）**：手机不能将 `localhost` 当作比赛电脑；需准备手机可访问的服务地址、HTTPS 和微信小程序合法域名配置，并验证小程序平台相关限制。不得把“关闭开发工具域名校验”视为真机部署方案。

两种模式的区别须在比赛前确定；无论哪种，AI 请求都通过服务端代理，不把第三方 API Key 放到小程序中。

## 5. 数据结构规格

### 5.1 `providers`（AI 服务配置）

| 字段 | 类型 | 约束 |
|---|---|---|
| id | TEXT | UUID，主键 |
| name | TEXT | 必填，显示名称 |
| adapter_type | TEXT | `openai_compatible` / `custom_async` / `comfyui` 等 |
| base_url | TEXT | 必填，经过地址校验 |
| model_id | TEXT | 必填 |
| encrypted_api_key | TEXT | 服务端加密保存；本地模型可为空 |
| settings_json | TEXT | JSON：尺寸、超时、扩展参数 |
| enabled | INTEGER | 0/1 |
| active | INTEGER | 0/1；最多一个有效激活配置 |
| last_test_status | TEXT | `untested/success/failed` |
| last_test_at | TEXT | ISO8601 时间 |
| created_at / updated_at | TEXT | ISO8601 时间 |

安全约束：API Key 更新采用“留空表示不变、输入新值表示替换”的语义；读取配置接口仅返回 `hasApiKey`，绝不返回原始密钥。后端需要限制 Provider 地址的协议、主机和跳转，防止任意 URL 请求带来的 SSRF 风险。

### 5.2 `generation_jobs`（AI 生图任务）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | UUID |
| provider_id / model_id | TEXT | 使用的服务与模型快照 |
| prompt / negative_prompt | TEXT | 实际提交的提示词 |
| reference_image_path | TEXT | 图生图输入，可为空 |

## 6. API 接口契约（建议）

统一响应结构：成功 `{ "success": true, "data": {...}, "requestId": "..." }`；失败 `{ "success": false, "error": { "code": "...", "message": "..." }, "requestId": "..." }`。HTTP 状态码与错误类型对应，禁止把第三方密钥和完整鉴权头透传给前端。

| 方法 | 路径 | 角色 | 功能 |
|---|---|---|---|
| GET | `/api/health` | 公开 | 健康检查 |
| POST | `/api/admin/login` | 公开 | 管理员登录 |
| POST | `/api/admin/logout` | 管理员 | 退出 |

| POST | `/api/admin/providers/:id/activate` | 管理员 | 激活配置 |

| GET | `/api/generations/:id` | 用户端 | 查询任务状态与结果 |

### 6.1 Provider Adapter 统一接口

```ts
interface ImageProviderAdapter {
  validateConfig(config: ProviderConfig): Promise<void>;
  generate(input: GenerateInput, config: ProviderConfig): Promise<
    | { kind: 'completed'; imageBytes: Buffer; mimeType: string }
    | { kind: 'pending'; remoteJobId: string }
  >;
  poll?(remoteJobId: string, config: ProviderConfig): Promise<
    | { kind: 'pending' }
    | { kind: 'completed'; imageBytes: Buffer; mimeType: string }
    | { kind: 'failed'; code: string; message: string }
  >;
}
```

- `openai_compatible` 适配器须核对目标平台的**图像生成**接口协议；“兼容聊天补全 API”并不自动具备相同生图协议。
- `custom_async` 适配器负责提交任务、轮询、提取图片结果。
- `comfyui` 适配器用于可选本地推理，不是 P0 前置条件。
- 适配器负责下载、验证并保存图片到本地，统一返回稳定的内部图片路径。
- 配置切换采用原子操作：测试通过后激活新配置；正在执行的任务保留原 Provider 快照。

## 7. Prompt 与生成质量规格

生成目标为“可用于服装印花的现代重构纹样”，重点突出：西兰卡普文化语义、传统符号拆解、几何重组、潮流/新中式视觉语言、清晰主体与可印花构图。

建议 Prompt 组装：

```text
文化元素：{传统纹样名称及寓意}
设计方法：符号解构、几何重组、节奏与对称关系
服装风格：{街头潮流/新中式/极简/科技感}
配色：{用户选择}
应用场景：{胸前印花/背部大图/局部装饰}
画面要求：主体完整、纹样边界清晰、背景简洁、避免复杂文字
用户补充：{自由输入}
```

**质量检查**：输出与用户关键词相关；主体可辨；几何结构具有设计感；服装叠加时视觉效果合理；失败时可重新生成。默认目标尺寸可设 `1024×1024`，但须以实际免费模型支持的尺寸为准。

## 8. 非功能规格与安全

### 8.1 成本

- 禁止默认开启付费服务、后付费、自动充值和自动续费。
- 管理员启用 Provider 前必须确认免费额度、调用限制及付款要求。
- 测试生成也计入实际调用；提供每日调用次数上限、单任务最大重试次数（默认 0 次自动重试）及冷却时间。
- 免费额度耗尽时停止真实请求并提示切换 Provider，不偷偷改用预置图片。

### 8.2 性能与可靠性

- 页面切换应流畅；图片懒加载与适当压缩。
- AI 请求超时默认可配置 120 秒；异步任务轮询要有最大时长与间隔。
- 对网络中断、401/403、429、5xx、返回非图片、图片 URL 失效分别处理。
- 每个任务具备唯一 ID；重复提交通过前端防抖和后端幂等策略控制。
- 本地生成图片和 SQLite 数据在重启后可用。

### 8.3 安全与隐私

- 第三方 API Key 仅在后端使用；`.env`、SQLite 数据文件、密钥材料、日志与生成图片目录不得提交公共仓库。
- 管理员接口全量鉴权；密码使用安全哈希；限制登录尝试次数。
- Provider Base URL 使用受限白名单/协议校验；禁止访问本机敏感服务与内网元数据地址。
- 联系方式只用于模拟订单；优先使用虚构数据。若实际收集个人信息，展示隐私说明并获取主动同意，按微信平台现行规则配置隐私保护能力。
- API 返回错误时不显示密钥、完整请求头或敏感配置。

### 8.4 兼容与资源

- 织机素材建议 MP4/H.264，单个视频建议不超过 20MB，按实际小程序包体积与网络能力决定资源放置方式。
- TD 动画可使用短 MP4/GIF；Style3D 输出透明 PNG，附印花区域相对坐标。
- 不把原始高精度 3D 模型作为小程序运行依赖。
- 如果真机运行，需要重新评估本地文件服务、HTTPS、域名与图片可访问性。
